# The systems audit, 6 Nov 2026

Before the games moved into this repository, each was audited for the systems it shares with the others: what each
version does, how they differ, which is best, and what makes moving one risky. Four of them became `@wb/core` (below);
the rest waited, each for a reason (`docs/decisions.md`, 12).

**Read the section for a system before promoting it** (the `promote` skill), so its next session starts from what is known
rather than auditing again. It is a snapshot: the games have changed since (Tethys v11.93.2, 7 Nov 2026, changed
`physics.js`), so check what it says against the code before acting on it. Line counts are from 7 Nov 2026.

Audited at: Rootshock `22991ec`, Overworld `b7b08c7`, Tethys `99b56dd`, Planet-Viewer `f16a02d` (each repository's `main`
on 6 Nov 2026; the same commits came in with their histories). Paths below are where the code lives now.

## Already in `@wb/core`

`packages/core/README.md` has the API. What the audit found, for the record:

- **Random numbers.** All four had mulberry32. Run side by side on 6 Nov 2026 (2000 draws × six seeds, and for Tethys 15
  seeds × 3000 draws), all gave identical numbers; `packages/core/test/golden.test.ts` pins them. Differences were in the
  wrapping only: Rootshock's class takes string seeds (FNV-1a) and saves its state; Overworld's is one module-wide stream
  and takes a seed or state of 0 as 1 (its `rng.js` keeps that); Tethys's is a closure (`mulberry(seed)` returns a function).
  Tethys's `hashStr` was the same function as Rootshock's `hashString` (FNV-1a).
- **Loop, meter, maths.** Rootshock's: `FixedLoop` (60 Hz, at most 8 steps a frame, the backlog dropped after a stall,
  `alpha` for drawing in between), `Meter` (mean and worst per part over half a second), `angDiff(a, b)` (the turn from a to
  b; note the order). Tethys keeps its variable step: a fixed step changes how it feels, and it was not tried.

## 1. Save storage

Three games persist, three ways. None migrates old saves step by step.

**Tethys**, `games/tethys/src/save.js` (144 lines):

- An async, callback store over sync backends, so the headless tests stay synchronous. IndexedDB `tethys` (version 1),
  object store `kv` with `keyPath: 'id'`; if that fails, localStorage under `tethys.kv.<id>`; then an in-memory map. API
  `storeAll`, `storeGet`, `storePut`, `storeDel`.
- Slots are records `{id, kind:'save', v: SAVE_V}` (`SAVE_V` 3), with a profile record beside them.
- Saves every 30 s, on `visibilitychange`, `pagehide` and on losing pointer lock. On `beforeunload` it also writes a
  synchronous localStorage shadow, `tethys.last`, merged at the next boot, because an IndexedDB write may not finish as the
  page closes. Asks for `navigator.storage.persist()`.
- Export and import as a `.json` file (`fileSave`, `filePick`); `saveImport` sanitises every field. Large typed arrays are
  run-length encoded and rounded to 3 decimals.
- Old versions are read tolerantly (a version 1 record without a spec gets its preset) rather than migrated.
- Coupling: the store layer is low; `saveRecord` and `startFrom` are the game's.

**Rootshock**, `games/rootshock/src/sim/save.ts` (216), `src/sim/run.ts` (93), `src/present/store.ts` (14):

- Plain JSON: whitelisted fields copied with `structuredClone`; entities by creation order and `world.newId()`; the world is
  rebuilt from the level, never saved; Float32Array nav fields as base64.
- localStorage only, through `readStore`/`writeStore`, which fail quietly. Key `rootshock-v2:run`.
- **`SAVE_VERSION` (25) must match exactly or the load throws, and `main.ts` deletes the save.** So every bump so far has
  deleted the runs saved before it. This is the strongest reason to fix saves.
- Saves on pause, `visibilitychange` and `pagehide` (synchronous, so it finishes). Continuing a run deletes its save, so a
  death is permanent.

**Overworld**, `games/overworld/js/save-load.js` (918):

- IndexedDB `overworld_zero`, store `saves`, key `overworld_zero_save`; the connection opened and closed per operation.
- `SAVE_VERSION` 6, `ACCEPTED_VERSIONS` [4, 5, 6], with field-presence migrations inside the readers.
- **A save that fails to load is copied to `overworld_zero_save_backup` first.** Good, and the others lack it.
- Snapshots with `structuredClone` before any `await`, so a turn cannot change it mid-write. Good.
- No runtime fallback: localStorage is used once, to move old saves into IndexedDB; if IndexedDB fails the player is told
  once that autosave failed.
- Saves every turn, the whole world's grids, and runs `JSON.stringify` on the whole save each turn only to log its size.
  An overlapping save is dropped, not queued. About 45 transient fields are stripped before saving.

**One origin for everything.** Every game is published under `william-are-buzbee.github.io`, so all of them share one
localStorage and one set of IndexedDB databases. Today's names: IndexedDB `tethys`, `overworld_zero`; localStorage
`tethys.kv.*`, `tethys.last`, `tethys.cam`, `tethys.fx`, and `rootshock-v2:run`, `:scale`, `:bright`, `:look`, `:swap`,
`:detail`. This is why saves survived the move. It also means **a shared store must keep each game's names** (or migrate
them, with the old saves tested), and a new game must namespace its keys.

**Best, combined:** Tethys's backend chain and its synchronous shadow for unload, Overworld's backup of a save that fails
to load and its snapshot before `await`, and something none has: a version number with stepwise migrations the game
supplies, so a bump upgrades a save instead of deleting it. The serialisers stay in each game.

**Before changing any game's saves:** capture real saves from the current code first (each game's tests can make them),
and test that they load after the change.

## 2. Audio

Both 3D games make every sound procedurally (no samples). Overworld has none. A session cannot hear: anything here
changes how a game sounds, so the person listens to it. Tethys's `AUDIO.md` notes that every number in it was chosen blind.

**Tethys**, `games/tethys/src/audio.js` (231 lines, 28 KB), tested by `test/audio.js` (against the stub's fake
`AudioContext`, whose parameters throw on NaN):

- One `AudioContext`, made by `initAudio()` from the menu's click; `updateAudio` calls `resume()` if it is suspended.
- Dry bus → the medium's lowpass and shelf → compressor → master; two convolver reverbs with impulse responses generated at
  boot; three early-reflection delay taps; a music bus.
- An 8-voice `PannerNode` pool (HRTF or equal-power by `Q.hrtf`): emitters sorted by loudness at the ear, the loudest 8
  borrow voices. Distance and absorption are the game's own curve (`rolloffFactor` 0).
- Parameters update at 20 Hz through `auP`, which drops anything not finite: `if(p&&isFinite(v))p.setTargetAtTime(...)`.
- An occlusion march, a 12-ray probe of the space round the listener 4 times a second, and `thump()` one-shots delayed by
  distance at the speed of sound in water (1480 m/s).

**Rootshock**, `games/rootshock/src/present/audio.ts` (486) and `soundscape.ts` (354), tested by `test/audio.test.ts`:

- `Audio.start()` from the Play click, resuming a context that exists.
- Master 0.55 → a lowpass for "under water" → `bus` and `amb`; three convolvers with generated impulse responses (0.45,
  1.6 and 3.4 s) mixed by the room's size.
- Private voice primitives: `tn` (an oscillator sweep with an envelope), `nz` (filtered noise), `chain(pan, muffle)`.
- Stereo only: a `StereoPanner`, a lowpass muffle and `(1 − d/RANGE[name])²` attenuation. No `PannerNode`, no HRTF.
  Distance and muffle come from the nav graph's sound field (`soundscape.hearing`).

**Shared:** starting the context on a gesture, a master bus, reverbs from generated impulse responses (two different
generators), and Tethys's NaN guard. The voice pool is Tethys's alone. **Best start:** the NaN-guarded setter and the
start-on-gesture, then one impulse-response generator the person has listened to.

## 3. Input

Neither 3D game has key rebinding or a gamepad. Add those when a game uses them, not before.

**Tethys**, `games/tethys/src/input.js` (35 lines; its state is declared in `player.js`):

- `keys[e.code]` booleans with codes written into `updatePlayer`; pointer lock, with drag-to-look when the lock is refused;
  `blur` clears every key. The window's resize handler lives here too.
- Touch by halves: the left half is a stick (drag ÷ 70 px, clamped to ±1; pulled past 1.5 it sprints); on the right, a drag
  looks (× 2.4), a tap (under 12 px and 350 ms) bites, a still hold grabs, two fingers use the ability.
- The handlers call the game directly (`bite()`, `ability()`, `playerLay()`, `toggleFP()`…). `test/steer.js` drives the
  touch stick through the stub, so a change here shows there.

**Rootshock**, `games/rootshock/src/present/controls.ts` (131), `src/sim/input.ts` (27), `src/present/touch.ts` (157):

- An `Input` struct per step (`forward`, `strafe`, `run`, `yaw`, `pitch`, `jump`, `crouch`…); `noInput()` gives an empty one.
- **`Controls.take()` holds a press until a step uses it**, so a click shorter than a step still counts; mouse movement
  gathers in `pending`, which the camera shows at once. Good: this is the part to promote first.
- Pointer lock with drag-look when refused; `everLocked` decides whether losing the lock pauses or falls back.
- Touch: a floating left stick (reach 52 px, dead zone 0.12, pushed past 1.4 × reach it runs), drag-look with pointer
  capture, seven SVG buttons. `onKey`, a map of code → function, carries the dev keys.

**Overworld**, `games/overworld/js/main.js` (983): tables (`DIR_MAP` for QWEASDZXC, the arrows and the numpad;
`SELF_KEYS`; `ACTION_MAP`), then one `keydown` listener with a long chain of conditions; left click steps toward a tile,
right click inspects, the wheel zooms (`canvasToWorld`). No touch. A roguelike's needs; nothing here for the 3D games.

**The template** (`tools/templates/game/src/present/keys.ts`) has held keys only.

**Best:** Rootshock's held-until-taken presses and pending look, and a touch stick whose reach, dead zone and run point are
parameters, since the two games' numbers differ and each game's feel depends on its own.

## 4. Noise

Three different algorithms, and each one's output is its worlds: change the noise and every world from every seed changes.

- **Tethys**, `games/tethys/src/util.js`: a permutation table shuffled by a Park-Miller generator (seed 1337); 2D value noise
  `vnoise` (bilinear, smoothstep), `fbm(x, y, octaves)` with lacunarity 2.07, `angNoise`. Its CLAUDE.md requires the home
  island (`ISLANDS[0]`) to stay bit-identical.
- **Planet-Viewer**, `labs/planet-viewer/core-math.js`: hash value noise with no table: `hashInt(x, y, seed)` (primes
  374761393 and 668265263, then `Math.imul(h ^ (h >>> 13), 1274126177)`), `noise2D`, `noise3D`, `fractalNoise3D`,
  `sphereNoise`. Seed 5 is its anchor.
- **Overworld**, `games/overworld/js/surface-gen.js`: Perlin gradient noise (8 gradients, fade 6t⁵ − 15t⁴ + 10t³, a
  permutation shuffled by the LCG 1103515245/12345), `createNoise2D(seed)` and `fbm(fn, x, y, {octaves, frequency,
  lacunarity, gain})`. Duplicated in its own `main.js` for the title screen (`_titleNoise2D`, `_titleFbm`).
- Rootshock has none (its `makeNoise` is a sound event in the game, not a noise function).

**When a new game needs noise:** promote Planet-Viewer's hash noise (seedable per call, 3D, no table), with golden values
taken from it first. Leave the existing games on their own unless the person agrees to regenerate their worlds.

## 5. Collision and physics

No game uses a physics library; Rapier was considered and rejected by Rootshock (`docs/decisions.md`, 7). The two 3D
games share algorithms, not code: a spatial hash, closest points between segments, verlet distance constraints.

**Tethys**, `games/tethys/src/physics.js` (409), tested by `test/physics.js` (the hash against brute force):

- Static colliders in a 2D bucket hash per streaming cell (16 m buckets, 15 × 15 a cell). Five shapes: sphere, capsule, pad
  (a disc riding the waves), ellipsoid (an affine unit sphere) and rock (a dodecahedron as 12 planes).
- `solidPush`: up to 3 relaxation passes; capsules by the closest point on the segment; rocks by the least-penetrated face
  (approximate at edges); ellipsoids by radial projection (not the true closest point). The inward part of the velocity is
  removed; a bit mask reports what was hit, for the sound.
- Bodies as three spheres (`bodyPush`); body against body O(n²) with Ericson's segment closest points (`segSeg`), split by
  mass, one pass. Chains (`simChain`): position-based, at most 39 points and 160 segments a rig, skinned rigidly with
  frames built from the chain (`rigSkin`).
- Coupled to the cells (`CELL`, `chunkAt`, `groundAt`, `waveH`) and, in `stepRigs`, to `combat.js`. The hash, `solidPush`,
  `segSeg`, `resolveBodies` and `simChain` without the grab are separable.

**Rootshock**, `games/rootshock/src/world/` and `src/sim/`:

- `grid.ts` (77): 0.25 m voxels in sparse `Int16Array` chunks of 16³, a map with numeric keys and a last-chunk cache.
- `shapes.ts` (84): plan-view circles and boxes extruded over a height (upright cylinders and boxes, not capsules), boxes
  turned on the plan, slab tests.
- `world.ts` (442): `overlap`, `groundBelow`, `ceilingAbove`, `sweep` (sub-steps, then 8 bisections), `pushOut` (up, then
  8 directions), `raycast` (Amanatides–Woo through the grid, slab tests on boxes, surfaces marched and bisected). Coupled to
  its level format.
- `sim/body.ts` (185): walking axis by axis with step-up, falling with ground snap, shoves that share momentum. No rotation.
- `sim/ragdoll.ts` (988): verlet points, 8 iterations of distance, hinge, pin and floor constraints, muscle tone towards a
  pose, sleep under 0.12 m/s for half a second, at most 16 awake, no randomness. `hold`, `bend`, `frameOf` and the world
  collision are generic; the rest is the cast's.

**Promote when** a third 3D game needs collision, starting from the generic pieces named above.

## 6. Camera

What the two 3D games share is one line: smoothing by `1 − exp(−k·dt)`. Tethys's is third person
(`games/tethys/src/player.js` `finishPlayer`: an arm from the body's length, a ground clamp and `solidPush`, its own up so it
never rolls, shake and a field-of-view kick behind `FX.camFx`; it allocates one vector a frame, line ~305). Rootshock's is
first person (`games/rootshock/src/present/camera.ts`, 117: eye height easing between standing, crouched and down, head bob,
shake and a jolt that eases off, and the flashlight's aim tangled into it). Nothing to promote yet.

## 7. Renderer and quality

- **Tethys**, `games/tethys/src/scene.js` (710): a quality table `Q` (numbers only, never code paths), the tier from the URL
  or a small touch screen, pixel ratio capped at 1.0 or 1.5. Deeply three r128: rewritten fog chunks, hand-read shadows,
  `onBeforeCompile` materials, a horizon pass that works round r128 clearing to the background.
- **Rootshock**, `src/present/render/view.ts` (55), `post.ts` (197) and `src/present/quality.ts` (90): pixel ratio
  `min(dpr, 1.5) × scale`; a post chain (bloom, exposure, grain); and the **`Governor`**: adaptive resolution over the
  steps [1, .85, .72, .6, .5, .42], judged over 1 s windows with the slowest 10% dropped, a step down kept only if frames
  get 10% quicker, back off doubling, a step up after 3 calm windows, the step kept per device (`rootshock-v2:scale`),
  touch starting at step 2. No imports; tested against a simulated GPU (`test/quality.test.ts`). The strongest single piece
  of code the audit found, and so far it has one user.
- Both cap the pixel ratio at 1.5 and start lower on touch; so does the template.

## 8. Dev tools

- **Tethys:** the readout (backquote, `'` or F3: frame rate, section timings, draws, triangles, heap and the world's
  state); live tuners as tables of `{k, lo, hi, step, min, max, d}` (`FOG_TUNE`, `AU_TUNE`, `CAM_TUNE`) with Backspace to
  reset; the effects list (`effects.js`, kept in `tethys.fx` with a version and a list of new defaults to push through);
  URL flags (`#low`, `#zoo`, `#lab=`, `#bench`…); `tp()`, `skip(days)`; the world map on `n`.
- **Rootshock:** `?dev` (a readout, keys for fly, god, bright, the collider overlay, the progression tracker, slow time and
  the arena's spawns, `window.rs`); `?fps`; `?dbg=` (`src/present/debug.ts`), a whitelist turned into shader `#define`s to
  switch stages of the picture off; the `Meter` (now `@wb/core`'s).
- **Overworld:** console helpers only (`js/debug.js`); no on-screen readout.
- **The template** has a `?dev` mode built on `@wb/core` (pause, step, slow time, the readout, `DEV_KEYS`). Candidates to
  promote when a second game wants them: Tethys's tuner tables, and its versioned settings in localStorage.

## 9. Grids, sight and paths

Different worlds, different needs. **Overworld** (`js/fov.js`, 787; `js/ai-utils.js`, 409): recursive shadowcasting over
8 octants with a sight budget, Bresenham line of sight, a breadth-first first step inside a box (`Int8Array`), a spatial
hash keyed by `"x,y"` strings (integer keys would be faster). **Rootshock** (`src/world/nav.ts`, 412): a 1 m lattice of
standing spots, edges for walking, dropping, lifts and climbing, Dijkstra distance fields with a binary heap and masks for
who may use what. The binary heap is the only common piece.

## 10. One user so far

- **Streaming under a frame budget** (Tethys, `src/chunks.js` 442 and `far.js`): cells built by `function*` generators
  that yield, run nearest first within what the last frame left of its time budget, one unloaded a frame; per-species
  `InstancedMesh` pools with a contiguous block per cell (`test/pool.js` checks placement does not depend on load order).
- **Drainage** (Planet-Viewer, `regional-drainage.js` 160): `routeFlow`, a padded priority flood (Barnes 2014) and D8 on
  typed arrays, with stream order. Overworld has a design note for drainage
  (`games/overworld/Notes/drainage-chunk-generator-design.md`): when it builds it, that is the second user.
- **Log and UI** (Overworld, `js/log.js` 77, `js/log-ui.js` 133, `js/modal.js` 15, `js/ui.js` 310): structured log
  entries with categories, tabs and mutes, a modal, an rAF coalescer for HUD updates.
- **The energy scheduler** (Overworld, inside `js/turn-loop.js` 613): action points by speed, a cap per input, a dormant
  radius with catch-up. A pattern, not separable code.

## 11. Test harnesses

- **Tethys:** tests that concatenate `src/` against a stubbed THREE (`test/stub.js`, 113: a partial THREE, a fake DOM, a
  virtual clock, a fake `AudioContext` that throws on NaN) and an acorn scope lint (`test/lint.js`). Note: the stub's
  `Matrix4.invert()` does nothing.
- **Rootshock:** Vitest, 510 tests; `test/layers.test.ts` (the sim never touches three.js or the page; the
  template has its own); probes that hash the cast every step for determinism (`test/probes/`).
- **Overworld:** `tools/check-modules.mjs` (every module parses, every import resolves), `tools/smoke.mjs` (boot, play,
  save, reload, resume, seed determinism; now its `smoke` script in CI), and `tools/ecology.mjs` (the world over several
  seeds, means and spreads, JSON to compare branches). The multi-seed harness is the pattern worth reusing: one seed is
  an anecdote.
- **Planet-Viewer:** `tools/smoke.mjs`, the whole generation stack in Node with no browser (its `test` script).
